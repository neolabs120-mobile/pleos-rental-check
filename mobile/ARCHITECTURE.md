# Flutter 이용자 앱

Flutter 앱은 차량용 앱과 같은 서버를 사용합니다. Pleos SDK·차량 접근 키는 기존 Kotlin/Compose 앱이 소유합니다.
휴대폰은 계정 인증으로 예약 소유권을 확인하고, 차량 QR 승인과 사진·체크리스트·기록 조회를 수행합니다.

| 경로 | 책임 |
|---|---|
| `lib/main.dart` | Material 3, 한국어, 주간/야간 테마, 로그인 상태에 따른 시작 화면 |
| `lib/screens/` | 화면별 폼과 동작. 사용자 화면을 한 파일에 모으지 않음 |
| `lib/state/rental_controller.dart` | 계정·예약·QR 대기 상태와 세션 복원 |
| `lib/data/rental_api.dart` | 서버 JSON·사진 통신, 타임아웃, 권한별 헤더, 오류 응답 |
| `lib/data/session_store.dart` | Keychain/Android 보안 저장소 인터페이스 |
| `lib/data/connection_link.dart` | 설정된 서버 origin과 QR 종류·토큰 검사 |
| `lib/models/rental_models.dart` | 계정·예약·관측 요약·사진·직접 확인의 타입 모델 |
| `lib/ui/` | 재사용 컴포넌트, 인증 사진 표시 |

## 세션과 전송 정책

- 세션에는 토큰·만료 시각·서버 origin만 보관하고, 비밀번호와 차량 앱 키는 보관하지 않습니다.
- 앱 재시작 시 만료와 origin을 확인한 뒤 `/api/account/me`로 세션을 검증합니다.
- 서버 주소를 바꾸면 이전 세션을 새 서버로 보내지 않고 기기에서 지웁니다. 오프라인 상태의 서버 변경은 이전 서버의 세션을 즉시 철회하지 못하므로 해당 서버 세션은 만료될 때까지 남을 수 있습니다.
- QR 토큰은 메모리에만 유지합니다. 별도의 Universal Links/App Links 등록 없이 앱 안의 스캐너/붙여넣기로 연결합니다.
- QR 스캔으로 서버 주소를 자동 변경하지 않습니다. 예약 차량의 승인 확인창을 거친 다음 서버에서 소유권·VIN을 검증합니다.
- 계정 API는 `Authorization: Bearer 계정토큰`, 사진 API는 `Authorization: Bearer 사진토큰`과 `X-Account-Token: 계정토큰`을 함께 사용합니다.
- 사진은 JPEG/PNG/WebP와 8MB를 1차 검사하고 서버가 실제 이미지 검증·재인코딩·EXIF 제거를 수행합니다. 자동 손상 판정은 하지 않습니다.
- 미리보기는 전송과 구분하며, 실패한 전송의 요청 ID를 유지합니다. 서버가 받은 사진의 중복 저장을 막습니다.
- 전송 연결 갱신 시 인수에서 반납 단계로 바뀌면 미전송 사진과 직접 확인을 이어 쓰지 않고 해당 단계의 서버 기록으로 초기화합니다.
- Android 사진 선택 중 프로세스가 종료된 경우 `retrieveLostData`로 복구한 사진의 항목을 이용자가 다시 선택합니다.
- 최종 제출 응답이 유실된 경우 소유자 기록을 조회해 실제 접수된 경우에만 접수 화면을 표시합니다.
- 카메라·QR 스캐너·보안 저장소의 실제 기기 동작은 기기별 확인이 필요합니다. 화면 테스트와 HTTP 클라이언트 시험이 이를 대신하지 않습니다.
