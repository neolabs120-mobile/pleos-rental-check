# 반납 마무리 · 0.4.0

차량·Flutter 0.4.0+15는 반납 마무리를 보완했습니다. 물건별 ‘챙겼어요’를 차량에서 확인하고 휴대폰으로 이어가며, 운영자가 등록한 주차장 입구·층·구역·주차면 안내를 봅니다. 사진 구도 가이드와 같은 항목의 인수·반납 비교, 계정·서버·기록별 암호화 임시 저장을 제공합니다. 배터리는 인수 때 실제 수신한 퍼센티지를 기준으로 부족분을 안내합니다.

Android Debug 100개·Release 98개, 서버 51개, Flutter 53개(선택 2개 제외), 분석 문제·Lint 오류0/기존 경고24. 읽기 전용 Pleos AVD의 새 반납 통합 11조건과 실제 웹 PNG/JPEG/WebP 선택·재시작 복구·직접 확인·최종 접수를 확인했습니다. 시험 배터리는 인수80%→반납72%, 기준80%·부족8%p였습니다.

충전 경유 요청은 실제 내비 경로에 전달되지만 해당 AVD의 경유지 조회 좌표는0,0입니다. 최종 목적지는 맞아도 충전 경유지는 앱에서 검증 완료로 표시하지 않고 내비에서 직접 확인하도록 안내합니다. 실차·정상 VIN Release 전체 흐름·Fold8 실물 촬영과 실제 단말 통신 단절은 미검증입니다. 새 영상은 올리지 않습니다.

## 이용자가 확인하는 순서

1. P에서 짐 메모를 남깁니다. 반납할 때 저장한 물건을 화면·음성으로 다시 안내하고, 실제로 살펴본 물건만 ‘챙겼어요’로 표시합니다. 수정한 메모의 이전 확인은 초기화합니다. 반납 저장 뒤 차량 메모는 고정되며 휴대폰에서 확인을 이어갑니다. 새 형식의 짐 메모가 있는 기록은 물건별 확인까지 저장해야 최종 제출할 수 있습니다. 과거 기록은 그대로 호환됩니다.
2. 반납 장소에서 운영자가 등록한 안내를 펼칩니다. 입구·층·구역·주차면을 최대4단계, 사진과 설명으로 받습니다. 시험 도식은 실제 주차장 사진과 구분해 표시합니다. 현재 GPS나 가까운 거리로 주차면 도착을 확정하지 않습니다.
3. 촬영 전 항목별 구도 도식을 보고 창문·소지품·외관 사진을 선택하거나 촬영합니다. 같은 예약·항목의 인수 사진과 반납 사진을 직접 비교합니다. 사진이 없으면 없다고 표시하며, 구도를 자르지 않고 보여줍니다. 실시간 카메라 오버레이·손상 자동 판정은 제공하지 않습니다.
4. 사진과 체크·메모는 전송 전에 기기에 암호화해 저장합니다. 앱을 다시 열면 같은 계정·서버·기록의 이어쓰기 카드가 나타납니다. 임시 자료는7일, 최대5건·직렬화40MB 제한이며, 전송되지 않은 사진에는 같은 요청 ID를 유지합니다. 저장 중·기기 저장·서버 저장·최종 접수 상태를 구분합니다. 서버 접수 번호를 받기 전에는 완료로 표시하지 않습니다.
5. 배터리 기준은 저장된 인수 관측값입니다. 현재 또는 반납 잔량으로 기준을 바꾸지 않으며 미수신·범위 밖·다른 VIN 값은 확인 불가로 둡니다. 부족분은 퍼센트포인트로 표시합니다. 운영자 등록 충전 경유지는 사용자가 승인하고 새 VIN/P/부족분을 확인한 뒤 Pleos에 요청합니다. 충전 요금·실시간 사용 가능 여부·자동 정산이나 반납 차단을 의미하지 않습니다.

## 실제 검증과 제한

독립 계정·DB·설정과 읽기 전용 Pleos2.1.0 ARM64 AVD5556에서 Debug 테스트 VIN·모의 GPS·표시된 시험 장소를 사용했습니다. 기존 사용자 예약은 바꾸지 않았습니다.

- 실제 SDK 통합 11조건: 소유자 QR 승인·인수, 미확인 짐 메모, 소유자 권한 인수 비교 자료 준비, 실제80→72 배터리와80기준/8부족, 주차 안내 팝업/도식, 경유지 좌표 불완전 시 확인 완료 금지, 열린 창문 우선, 비점유 상태의 메모 TTS 시작/완료, 차량 물건별 확인, 서버 값 일치, 반납 저장·동기화·메모 고정.
- 웹은 같은 새 기록에서 실제 선택기로 PNG/JPEG/WebP3장을 골라 전송했습니다. 전송 전 PNG와 체크를 저장한 뒤 페이지를 다시 열어 이어쓰기·복원을 확인했습니다. 인수·반납 비교, 물건별 미확인 제출 차단, 직접 확인3종·메모·최종 확인창·서버 접수 번호를 확인했습니다. 인수 비교 사진3장은 일반 소유자 API로 준비한 표시된 시험 자료이고 실차 사진이 아닙니다.
- 오프라인 편집·세션 유효성/401 구분·프로세스 중단 복구·요청 ID 유지·계정/서버 분리는 자동 검사로 검증했습니다. 실폰 네트워크 단절·장시간 대용량 저장 성능을 검증한 결과는 아닙니다.
- 충전 경유 요청은 공식 `requestRouteWithWaypoints`를 사용합니다. 실제 Navigation 로그에는 요청 좌표·경로의 경유지가 맞게 반영됐지만, 공개 `onWayPointInfo`는0,0을 반환했습니다. 이름만 맞는 응답으로 좌표를 추정하지 않습니다. 앱은 ‘반납 경로는 확인했지만 충전 경유지 좌표를 확인하지 못했어요’와 직접 확인 안내를 표시합니다.
- 음성 인식·도착 제안13조건은 [0.3.0 검증](VOICE_ARRIVAL_0.3.0.md)을 유지합니다. 이번 집중 통합에서는 메모 직접 입력과 실제 TTS를 사용했고 한국어 STT 전체 조건을 반복했다고 세지 않습니다.

좌석 신호는 물건 감지가 아닙니다. 창문 확인·소지품 사진·직접 확인 요구를 유지하며, 앱 점검 접수는 사업자의 실제 반납 승인·요금 정산과 별도입니다. Release의 실제 VIN·HTTPS 검증은 유지합니다. 정상 VIN·실차·실폰 QR/촬영·iOS는 추가 확인이 필요합니다.

## 운영자 안내 등록

기존 예약 장소 필드는 유지하며 `parkingSteps`와 `chargingStops`가 없으면 빈 목록으로 처리합니다. 이미지에는 외부 URL을 사용하지 않고 JPEG/PNG/WebP를 검증한 뒤1024px이하 JPEG로 정규화해 EXIF를 제거합니다. 단계4개·이미지당Base64400KB이하, 충전소3개까지입니다.

```sh
python server/issue_booking.py --base-url http://127.0.0.1:8788 --email 본인_시험계정 --vin TEST0000000000001 --vehicle-name 체험차량 --demo --return-guide-json /absolute/path/return-guide.json
```

안내 JSON의 최소 예시입니다. 실제 운영에서는 사업자가 확인한 장소·주소·좌표·주차 조건을 사용합니다.

```json
{"name":"시험 반납 장소","address":"시험 주소","latitude":37.48544722,"longitude":127.03636666,"isTest":true,"parkingSteps":[{"title":"시험 입구","detail":"실제 주차장이 아닌 안내 예시"}],"chargingStops":[{"name":"시험 충전 경유지","address":"실제 충전소 확인 필요","latitude":37.41275833,"longitude":127.09481944}]}
```
