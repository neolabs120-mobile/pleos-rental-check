# Flutter 0.2.7 · 상단 차량 연결 카드 · 2026-11-01

완료 예약이 쌓이면 홈 아래의 QR 버튼까지 스크롤해야 했습니다. 이제 홈 상단의 연결 카드에서 **차량 QR 스캔**과 **카메라가 없나요? 링크 입력**을 먼저 선택할 수 있습니다. 홈의 ‘이용할 예약’에는 미제출 예약을 표시하고, 완료된 이용과 영수증은 기존 기록 탭에 보관합니다. 홈의 ‘지난 이용 기록 보기’로도 접근할 수 있으며 탭 이동 시 목록을 처음부터 보여줍니다.

QR 버튼은 기존 스캔 화면을 열고, 링크 입력은 카메라를 시작하지 않고 붙여넣기 화면을 엽니다. 두 경로 모두 기존 서버·토큰 검증을 거쳐 예약을 다시 조회합니다. 링크 확인만으로 차량 연결이 완료되지 않으며, 선택한 예약/VIN을 확인하는 별도 연결 승인이 필요합니다. 수동 예약번호·코드 연결과 사진 전송 링크 이어가기도 유지합니다.

## 검증

- Flutter 정적 분석 문제 0, 자동 테스트 **40개 통과**, 선택 실서버 통합 테스트 2개 제외.
- 새 회귀 테스트 5개: 완료 예약 12개가 있는 320·360·840 폭에서 QR/링크 첫 화면 노출과 기록 보존, 직접 링크 입력의 카메라 미시작·다른 서버 차단·승인 대기, 360 폭/글자 1.5배에서 완료 기록 접근.
- 기존 QR 재조회·연결 승인 테스트도 통과했습니다. 번호·코드 수동 입력을 기본 흐름에 추가하지 않았습니다.
- 실제 로컬 Flutter 웹에서 로그인·320/360 폭의 연결 카드·QR 진입·직접 링크 입력·다른 서버 링크 거절·기록 탭·기존 접수 기록과 사진 조회를 확인했습니다. 새 예약이나 반납 접수는 만들지 않았습니다.
- 새 서명된 Release APK를 읽기 전용 Pleos AVD 실행본에 설치하고 실제 첫 화면·실행 프로세스·크래시 없음을 확인했습니다. 원본 AVD에 앱을 덮어쓰지 않았습니다.
- APK 서명·버전·debuggable=false·16KB 정렬 검사를 통과했습니다. 기존 키·APK·영상과 사용자·예약·점검·사진·직접 확인 행을 보존했습니다. 웹 재로그인에 따른 세션·요청 제한 기록만 정상 갱신됐습니다.

이번 변경은 Flutter 홈과 연결 진입 UI입니다. 차량 SDK·TTS·서버 로직을 바꾸거나 전체 SDK 반납 시험을 다시 수행하지 않았습니다. 차량 앱의 Android Release 80개·전체 대여/반납·음성 검증은 이전 0.2.6/0.2.5 기록을 따릅니다. 실폰 카메라 QR·촬영·실차·정상 VIN을 사용하는 Release 전체 흐름은 미검증입니다.

## 실행·다시 빌드하기

휴대폰 Release는 HTTPS API 주소가 필요합니다. 설정에서 주소를 지정하고 예약 이메일로 로그인합니다. 기본 `https://rental.invalid`는 운영 서버가 아니며 공개 운영 서버는 별도로 준비해야 합니다. localhost 웹만 Debug 빌드로 시험했고 Release의 HTTPS·실제 차량 VIN 검증은 유지합니다.

```sh
cd mobile
flutter pub get
flutter analyze
flutter test
flutter build apk --release --build-name=0.2.7 --build-number=11
```

이 저장소의 Release 빌드는 unsigned APK를 만듭니다. [기존 배포 서명 절차](RELEASE_SUBMISSION_0.2.6.md#다시-빌드하기)에 따라 zipalign 후 개인 배포 키로 서명·검증합니다. 공개 APK를 갱신할 때는 기존 배포 키를 재사용해야 하며 비밀번호와 키를 저장소에 넣지 않습니다.
