# Pleos API 활용 현황 · 0.4.2

Vehicle·SpeechToText·TextToSpeech·FusedLocation·NaviHelper의 5개 SDK 계열을 연결했습니다. 계열 수와 전체 API 사용률을 구분하며, 차량 쓰기 API는 사용하지 않습니다.

| SDK | 사용 기능 | 확인한 범위 |
|---|---|---|
| Vehicle2.3.2 | VIN/P·창문·문/트렁크·잠금·좌석·배터리·주행거리·연료·타이어 기준·경고 조회, 0.4.2부터 조명(Light)·방향지시등(TurnSignal)·와이퍼(Wiper)·유리 열선(HVAC)·핸들 열선(SteeringWheel)·사이드미러 열선(SideMirror) 읽기 | 고정 읽기 인터페이스10개·신호11종. 0.4.0은 실제 인수 배터리를 기준으로 현재/반납 부족분 계산 |
| SpeechToText3.3.1 | ON_DEVICE 한국어 짐 메모 후보 | 0.3.0 생성 PCM → 실제 최종 콜백·사용자 확인 저장. 마이크 입력 품질은 별도 |
| TextToSpeech3.3.1 | 도착 준비·짐 메모·점유 좌석 안내 | 0.3.0 실제 시작/완료. PCM 출력·좌석음성10조건 선행0.2.5 근거 유지 |
| FusedLocation1.1.3 | 전경 새 위치·직선거리·근처인지 참고 | 실제 AVD 모의 GPS 수신. 실차 GPS 정확도·지정 주차구역 판단과 구분 |
| NaviHelper3.0.5 | 승인한 반납 목적지·충전 경유 요청·목적지/경유지/안내 상태·내비 화면 | 0.4.0 실제 경유 요청 반영. AVD 경유지 조회0,0으로 좌표 검증 보류·직접 확인 안내 |

Vehicle의 조회·변화 구독은 실제 지원 영역을 따릅니다. 좌석은 같은 Vehicle Service의 vehicle-aidl1.1.1 원시 정수1=비점유,2=점유,그 외=확인 불가로 정상화합니다. SDK Boolean을 단순 반전하지 않습니다. 좌석 신호로 사람과 짐을 구분할 수 없고, 비점유도 소지품 없음의 증거가 아닙니다.

이전0.2.5 스냅샷에서는 신호11종 중8종이 수신됐고 VIN 미수신·EV의 연료 미지원·경고 권한 거부가 남았습니다. Tire 값은 현재 공기압이 아닌 저압 기준입니다. 새0.3.0 시험을 전체 차량 신호 재검증이나 정상 VIN 복구로 설명하지 않습니다. 알려진 Debug AVD의 명시적 테스트 VIN만 허용하고 Release의 실제 VIN 검증을 유지합니다.

새 STT는 버튼을 누른 경우에만 켜며 STT_SERVICE 권한을 사용합니다. 원본 음성·인식 원문·현재 차량 좌표는 서버에 보관하지 않습니다. 확인한 장소/물건 메모만 반납 기록에 포함하고 사진·직접 확인 요구는 유지합니다.

계정·예약·QR·사진·접수는 자체 서버/Flutter 기능입니다. Flutter는 차량 SDK를 직접 호출하지 않습니다. Gleo·원격 제어·물품 감지는 구현하지 않았습니다. [0.3.0 구현·실제13조건](VOICE_ARRIVAL_0.3.0.md), [공식 SDK 구성](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/).

0.4.0 실제80→72%를 수신해 인수 기준80%·부족8%p를 유지했습니다. 충전 경유는 공식 API를 사용하지만 해당AVD의 onWayPointInfo 좌표0,0을 정상 좌표로 대체하지 않습니다. 단계형 주차장 안내·사진 비교·임시 저장·물건별 확인은 자체 앱/서버 기능입니다. [0.4.0 구현과 검증](RETURN_COMPLETION_0.4.0.md).
